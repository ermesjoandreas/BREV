# The whole UniFFI surface of app/Generated/BrevCore.swift (docs/PHASE2_DESIGN.md
# §2.2; docs/PHASE3_DESIGN.md §5.6; docs/PHASE4_DESIGN.md §5.4;
# docs/AUTHORSHIP.md §3.1, §6), which
# scripts/test.sh compares with the
# bindings it just generated (docs/DECISIONS.md D-0064). Content leaves Rust
# only as OpenText.chunk's 960-byte results; records carry ids, metadata and
# identity codes (docs/PHASE3_DESIGN.md §6.4), and addresses only as OpenText
# handles. Invite codes cross as ASCII bytes (Data in, Data out); they are
# not message content (CLAUDE.md §5 Phase 4).
#
# Two kinds of lines: the name of every function Rust exports
# (uniffi_brev_core_fn_…), and every line of the bindings that names a
# FfiConverter type, with its leading and trailing blanks cut (comment lines
# left out). Every value that crosses the FFI goes through a converter, so a
# new export, argument, result, record field, enum payload or type changes a
# line here: a Vec<u16>, for example, brings a FfiConverterSequenceUInt16.
# The comparison is of sorted lists: the order and the comments here are
# free, but a line counts as often as it is listed. When the FFI changes,
# review what crosses, then update this file.
